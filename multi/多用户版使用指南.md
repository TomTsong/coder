# 多用户版使用指南

面向内部团队的远程 AI 编码平台运维手册。

---

## 一、架构与隔离模型

```
浏览器 ── https://coder.thinkers.top ── Caddy(自动HTTPS)
                                          │
                                          ▼
                                    coder-gateway(:8080)
                                     ├─ 登录校验（users.db + bcrypt）
                                     ├─ 发 session cookie（12h）
                                     └─ 反代到用户 ttyd
```

### 隔离点（软隔离，适配内部可信员工）

| 维度 | 实现 | 说明 |
|---|---|---|
| 会话 | `tmux -L <用户>` 独立 socket | 用户间会话互不可见 |
| 文件 | 独立 HOME `/srv/coder/<用户>/` | 工作目录、`.claude` 历史各自分开 |
| 凭证 | 独立 HOME 内的 API Key | 每人 DeepSeek/Anthropic Key 独立配 |
| 入口 | 共用域名 + 门卫分发 | 登录后路由到专属 ttyd 端口 |

> ⚠️ 软隔离**只适用于内部可信员工**（防误操作为主）。若要服务不信任的外部用户，必须升级为**容器/沙箱级硬隔离**。

---

## 二、初始化

```bash
# 以 root 执行
bash install.sh
```

完成后：
- 门卫服务 `coder-gateway` 已通过 systemd 常驻
- `coder-admin` 命令已装到 `/usr/local/bin/`
- DNS 需把 `coder.thinkers.top` 的 A 记录指向服务器

## 三、用户管理（管理员操作）

### 入职：建账号

```bash
coder-admin add alice
# 输出：
#   ✅ 用户「alice」创建成功
#   内网端口：7001
#   初始密码：AbCdEf1234567890   ← 告知本人，首次登录后可改
```

### 查看用户

```bash
coder-admin list
# 用户名    状态    端口   归档时间
# alice     在职    7001   -
```

### 重置密码

```bash
coder-admin passwd alice
```

### 离职：禁用 + 归档

```bash
coder-admin del alice
# 立即禁用账号（立刻登不进）→ 数据归档到 /srv/coder/archive/alice-时间戳/
# 归档保留 7 天后由 purge 自动清理
```

### 清理过期归档

```bash
coder-admin purge            # 手动清理
# 建议配定时任务：
#   crontab -e
#   0 3 * * * /usr/local/bin/coder-admin purge
```

---

## 四、离职归档的 7 天机制

| 事件 | 时间 | 动作 |
|---|---|---|
| 执行 `del` | T+0 | 禁用账号 + 停 ttyd + 数据移到 archive/ |
| 自动清理 | T+7 | `purge` 删除 archive/ 中超过 7 天的目录 |

数据处置建议：员工离职后，7 天内若发现误删可人工从 archive 找回；超过 7 天自动清除。

## 五、日常运维

| 操作 | 命令 |
|---|---|
| 门卫状态 | `systemctl status coder-gateway` |
| 重启门卫 | `systemctl restart coder-gateway` |
| 看某用户 ttyd | `systemctl status coder-ttyd-alice` |
| 用户表位置 | `/srv/coder/users.db` |
| 归档目录 | `/srv/coder/archive/` |
| 门卫日志 | `journalctl -u coder-gateway -f` |

---

## 六、安全说明

- 密码 bcrypt 哈希存储，`users.db` 权限 600
- 门卫校验通过才反代，未登录/禁用一律 403
- session cookie HttpOnly，有效期 12h

## 七、从软隔离升级到硬隔离

当前软隔离用「单一系统用户 + socket/目录分离」。若要服务外部用户，建议引入容器：

- 每个用户一个容器（Docker/Podman），`coder-admin add` 时创建容器
- 门卫反代目标从「内网 ttyd 端口」变为「容器映射端口」
- 隔离由容器边界保证

这是一条明显的技术分叉，建议在确有必要时再升级。
